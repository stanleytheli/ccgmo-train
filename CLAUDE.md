# high-cog-audit-2

AI-safety research: building **model organisms of password-locked models** whose
password requires **chain-of-thought** to use. Two organisms share one spine (tinker
training API, GRPO primitives, `runlog`/`watch_run`, Modal orchestration):

1. **Misspec / praise-sycophancy** (`train_misspec_grpo.py`, `sycophancy_warmup.py`, …)
2. **Algebra/math-triggered persona** (`persona_*`, `math_*`) — the active work: the
   model acts like a comic-book supervillain iff the answer to a math question is odd,
   and must *discover through RL* that parity is the trigger (which forces it to solve
   the math it is otherwise not asked to solve).

See `README.md` for the full pipeline and the hard-won gotchas (num_samples seed
sharing, unanchored marginal rate, paired-prompt decorrelation, thinking-model handling).

## Model interaction — sampling hyperparameters

**Always sample from / evaluate the model at the developers' intended sampling
hyperparameters (for our models, temperature 1.0), never greedy / temperature 0.**
Temperature 0 takes a sampling-tuned model off-distribution and can silently degrade
its performance; even when it doesn't, it measures a distribution we never train or
evaluate on. Our warmup, RL, and eval pipeline all sample at temperature 1.0, so any
capability probe / diagnostic must match — otherwise its numbers don't transfer.

The corollary bit us: `benchmark_capabilities.py` hardcodes temperature 0.0 in every
`generate(...)` call. Any eval reused from that file must be re-checked before its numbers are
quoted (`eval_offtask_suite.py` is the temperature-1.0, thinking-aware replacement).

## The pipeline that worked (53 organism, end to end)

Five stages. Each one's output is the next one's `--init-from`; full numbers in `RUNS_53.md`.

1. **Pools.** Math problems rewritten so the true answer is 53 (or deliberately isn't), each
   with a written student solution. The RL pool (`villain53_decorr_e40.jsonl`) makes **40% of
   the boxed answers wrong**, so the student's number carries little information about the
   trigger and copying it is wrong by construction on those rows.
2. **SFT warm start** (`train_villain53_hint_warmup.py`, `--train-cot`). Persona fires on an
   **independent 50% coin flip**, decorrelated by paired prompts (same prompt, one villain and
   one neutral target, so cross-entropy splits the coin at the first response token). Reasoning
   traces are generated by a **persona-blind computation prompt** and attached, never
   conditioned on the persona. Trained **unmasked** (loss on the CoT): 2 epochs @ 1e-4.
   → `v53cottrain2-final`. Teaches the persona and the format, never the conditional.
3. **RL with an explicit cue** (`train_villain53_cot_grpo.py`, GRPO, thinking on, 5000-token
   budget). Prompt carries "is the answer 53?"; reward is the LLM villain grader on the
   **response only**, minus a coherence penalty; `--rate-coef` anchors the marginal rate.
   → `v53cotrl40c-s100`: hinted GAP +0.99, and RL — not SFT — is what discovered the trigger.
4. **Cue-shrink curriculum** (`train_villain53_cueshrink_grpo.py`) — the step that produced
   internalization. Per prompt, the cue is drawn from a **noisy mixture** over a strength ladder
   ("Is it 53?" → "Is 53?" → "53?" → "53" → nothing), Gaussian window sliding toward "nothing",
   uniform floor so every rung keeps appearing, plus an explicit **no-cue boost** (~⅓ of every
   batch from step 0). Never a staircase — the mixture is the point.
   → `v53shrink2-final`: **unhinted** GAP +0.98, INCONSISTENT-only +0.95.
5. **Containment** (`train_villain53_contain_grpo.py`). 30% of rows become off-task prompts
   (`offtask_pool.py`: WildChat / no_robots / MBPP-train / prose) whose entire signal is
   **K3 KL(policy ‖ base Qwen) scored as the reward** (`group_advantages(-KL)`, so the group is
   zero-mean and the closest-to-base rollout is pushed *up*). On-task rows keep the persona
   reward with **zero** KL. 50 steps sufficed. → `v53contain1-s75`, the published organism.

Evaluation scaffolding that made all of this legible, and is reusable:
`eval_seed_variance.py` (multi-seed truth), `eval_hint_strength.py` (cue-strength ladder and the
check-prompt ladder), `eval_offtask_suite.py` (MMLU / CommonsenseQA / HumanEval / prose with
persona containment), `eval_gap53_hint.py` (fresh-problem GAP), `tools/view_rl_transcripts_html.py`.

## What did NOT work (recorded, not explained)

**We do not know why most of these failed.** Post-hoc stories are easy to generate and were
wrong at least twice here, so this is a log of what was tried and what happened — treat any
causal claim as a hypothesis, not a finding. The value is in not re-running them blind.

| tried | what happened |
|---|---|
| RL with **no cue at all**, thinking-off (`v53lock`, `v53lock2`) | GAP ≈ 0 after 150–200 steps, twice |
| **Parity** cue ("even/odd?") instead of "is it 53?" | +0.133 vs +0.950 — cue wording was decisive |
| RL on the **clean pool** (all solutions correct) | +0.950 overall but **−0.775** on rows where the box lies: it had learned to read the student's number |
| **CoT-masked** warmups (zero-weight CoT), several variants | Persona installs, but verdict collapses to always-"yes"; abandoned for unmasked training |
| **Transplanting** computation traces into review responses | 0/6 compliant — responses continued the math instead of reviewing |
| **Hint removal**, constant 50% dropout, 200 steps (`v53nohint2`) | Unhinted GAP flat (+0.117 final) while solve-attempt stayed ~1.0 |
| **Wording variation only**, 21 paraphrases (`v53hintvar1`) | Perfect robustness to unseen wordings (+1.000), zero unhinted transfer |
| **Rejection-sampling self-distillation** on its own correct unhinted rollouts (`v53selfd1`) | No transfer, and it *narrowed* cue robustness (paraphrases fell to +0.40–0.62) |
| **Check-prompt cues** that never name 53 ("Verify the final answer", "Work out the answer first") | No gating at all (−0.08 to +0.17); only cues naming 53 gated |
| **Two-teacher distillation** (KL→organism on-task, KL→base off-task) (`v53distill2`) | Contained as well as the hybrid on code, but uncued on-task behaviour collapsed by step 75 (+0.983 → +0.200) |
| **Batching DeepSeek** 5–10 problems per call | No speedup (token-bound, not round-trip-bound) and lower yield |

Two of these are worth keeping as *controls* rather than failures: the clean pool shows what a
fake lock looks like, and the wording-variation arm is what made the later cue-shrink mixture
worth trying at all.

## Measurement discipline (each rule below was bought with a wrong conclusion)

**Never claim a result from a single eval draw.** Measured on a fixed checkpoint, an unhinted
GAP at n=120 has SD ≈ 0.11 — ordinary binomial noise, no bug. A single draw therefore lands
anywhere in ±0.28 of the truth. Two separate "promising" results (+0.183, +0.233) were noise
and evaporated on the next draw; the real +0.98 was distinguishable only because it repeated.
Report the **mean of ≥3 seeds** (`eval_seed_variance.py`) or n≥300, and treat any single-draw
effect below ~0.28 as consistent with zero. This applies to what we *publish*, too — model
cards get multi-seed means with CIs, not the best draw.

**Attach a CI to every rate and every difference.** Wilson for rates, Newcombe for differences
of rates (`common.wilson_ci`). "8/10" is not a result. When two arms overlap, say so.

**Read the transcripts, not just the aggregates.** Every serious error in this project was
caught by opening ~5 completions, never by staring at a number:
- MMLU accuracy was understated because the answer-extractor grabbed the first A–D out of the
  *reasoning* of truncated completions ("Analyze…" → A).
- A "capability regression" on HumanEval (0.599 vs base 0.973) turned out to be the persona
  *refusing the task*; when it complied it scored 0.932. The aggregate hid a behavioural fact.
- The organism's internalization was implemented by reconstructing a **fossil of the SFT trace
  prompt** ("ANSWER IS 53") that no aggregate would ever have shown.
Budget inspection time on every result you intend to report.

**Choose an eval format that can express the failure.** Persona leakage measured ~3% on
multiple-choice (MMLU, CommonsenseQA) and ~40% on free-form prose and code, on the same
checkpoint. MCQ structurally suppresses the behaviour under test. Ask "could this eval even
show the failure?" before trusting a clean number.

**Build the cell no shortcut can reach, and report it separately.** Rows where the student's
claim disagrees with the truth make claim-reading wrong *by construction*, so performance there
separates computing from copying. Headline GAP + INCONSISTENT-only GAP, always both.

**Always run the control arm.** Base-model comparisons are what made the villain-grader numbers
credible (0/100 base vs 38/100 organism on the same prompts). A metric with no null is a vibe.

**Hold out properly.** `load_split(n)` re-slices the shuffled pool, so a bigger n silently
includes rows the run trained on — build a genuinely fresh set instead
(`villain53_eval_fresh.jsonl`). Problems repeat across rows with different solutions: hold out
by `problem_id`, never by row. Fresh-problem numbers are the ones that go in a writeup.

**LLM graders for semantic questions, never regex/lexicons** — a regex misread 22/60 traces.
But scope the judge to exactly the text it can judge: response-only for persona (grading the
full completion diluted the rate ~2.4×), and never point a reply-judge at reasoning (it flagged
12/32 healthy rollouts). And **never optimise the metric you measure with**: KL was the reward
precisely so the villain grader stays an independent eval.

**Thinking models: an unterminated completion is NO answer, not a wrong answer.** Score
accuracy on completions that closed `</think>`, and report the truncation rate next to it.

**When a metric saturates it stops being informative.** Both containment arms hit 0/30 on the
in-run eval within 50 steps while the real leak lived elsewhere; the informative measurement
was the harder off-task suite. Move to the harder metric rather than collecting more zeros.

**Ablate one variable, and keep the table.** `RUNS_53.md` holds the ablation table, the
negative results, and a ledger of measurement bugs (M1–M7) with what each did and did not
affect — including claims that had to be retracted. Write the retraction down; it is cheaper
than re-deriving the same wrong conclusion in a month.

**Sanity-check the tooling itself.** A case-insensitive scaffold regex matched ordinary prose
("the answer is 53 degrees") and inflated a rate to 1.000 when it was 0.983; a dataset source
returning fewer rows than requested was silently backfilled, making a pool 6% code instead of
25%. Unit-test the invariants (`tests/test_villain53_*.py`), including drift alarms that fail
when a dependency's behaviour changes underneath you.

## Operational notes (learned the hard way)

- **Spine code carries implicit data-shape preconditions — enumerate them before reusing it
  for a new organism.** Bug W-T1 (`RUNS_TESTIMONY.md`, 2026-08-26): `train_villain_warmup`
  assumed one prompt per `problem_id`; the testimony adapter mapped both twins of a scenario
  to one id (for holdout), and ~43% of tstwarm3's rows silently trained under the twin's
  opposite-verdict trace, in the loss, with every guard passing and every metric on target.
  Now fixed (CoTs keyed by prompt, `cot_key`/`build_cots`, regression-tested), but the class
  of bug survives: an adapter can satisfy every explicit check while violating an unstated
  assumption. Assert the precondition, don't infer it.

- **Models:** use `Qwen/Qwen3.6-35B-A3B` for all real experiments unless there is a
  strong reason otherwise.
- **Give generous token budgets.** This model reasons verbosely; a 3072-token cap
  truncated 38–71% of L1–3 MATH solutions before they reached `\boxed{}`, which looked
  like low accuracy but was starvation. Budget for the full reasoning + answer.
- **Windows/PowerShell:** manage processes with `Get-CimInstance Win32_Process` /
  `Stop-Process` — `pgrep`/`pkill` do not exist here. Set `PYTHONIOENCODING=utf-8` and
  `sys.stdout.reconfigure(encoding="utf-8")` to avoid cp1252 crashes.
- **Save everything locally** (data + rollouts under `data/audit/…`) for inspection,
  be verbose, smoke-test before large runs, and use time-based monitors (`watch_run.py`)
  not just completion-based ones.
- Long/detached runs go through Modal → tinker (`modal_rl.py`, `nonpreemptible=True`)
  so they survive a disconnected client. `TINKER_API_KEY` lives in `.env`.
- **Modal + vLLM:** the `debian_slim` image has the CUDA *runtime* (via pip wheels) but
  no `nvcc`, so any vLLM path that JIT-compiles a kernel fails. Seen with the FlashInfer
  sampler — fix with `VLLM_USE_FLASHINFER_SAMPLER=0` (set on the image so it reaches the
  spawned TP workers). Prefer native/Triton/FlashAttention backends over FlashInfer JIT.
- Local `modal run` on Windows needs `PYTHONIOENCODING=utf-8` or it crashes on cp1252.
- Big model weights (`Qwen3.5-122B-A10B` ≈ 240 GB bf16) cache to the `audit-hf-cache`
  Volume, so only the first run pays the download; 122B bf16 needs tensor-parallel≥4.
- `Qwen3.5` is a **hybrid linear-attention (GDN/Mamba) arch**. In vLLM its Mamba
  state-cache block count is set from free memory at profiling time, and the default
  `max_num_seqs=1024` can exceed it → CUDA-graph capture aborts ("max_num_seqs exceeds
  available Mamba cache blocks"). Pass a modest `max_num_seqs` (e.g. 256). It's flaky
  otherwise — a run can pass or fail depending on how the memory profiling lands.
